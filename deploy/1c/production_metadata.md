# Производственный модуль MOVA: интеграция с 1С

## Основной документ

Новый документ создавать не требуется. Производственная заявка MOVA является
представлением стандартного документа 1С `ЗаказНаПеремещение`.

Используемые реквизиты:

- `Организация`
- `ОрганизацияПолучатель`
- `СкладОтправитель`
- `СкладПолучатель`
- `ЖелаемаяДатаПоступления`
- `Ответственный`
- `Подразделение`
- `Статус`
- `ХозяйственнаяОперация`
- `СпособДоставки`
- `ВариантПриемкиТоваров`
- `Назначение`
- `Комментарий`

Табличная часть `Товары`:

- `Номенклатура`
- `Характеристика`
- `Серия`
- `Количество`
- `Упаковка`
- `Назначение`
- `НачалоОтгрузки`
- `ОкончаниеПоступления`

## Дополнительные реквизиты заказа

Чтобы отличать заказы MOVA от остальных заказов на перемещение, использовать
стандартную табличную часть `ДополнительныеРеквизиты`.

Необходимые свойства:

- `MOVA_ПроизводственнаяЗаявка`: булево
- `MOVA_ВидПроцесса`: Сырье / Розлив / ГотоваяПродукция / Возврат
- `MOVA_Направление`: Пиво / Лимонад / Тара / СоСклада / СПроизводства
- `MOVA_АвторUID`: строка
- `MOVA_СвязанныйЗаказUID`: строка для парных перемещений
- `MOVA_ПартияРозлива`: строка
- `MOVA_ОперацияСПартией`: Этикетка / Передатирование

Такое решение не изменяет типовую структуру документа и позволяет фильтровать
только заказы, созданные или обслуживаемые MOVA.

## Объекты, которых не хватает в типовой 1С

`ЗаказНаПеремещение` покрывает движение товаров, но не хранит шаблоны,
производственные партии и результат розлива. Для реализации ТЗ необходимы
следующие новые объекты расширения.

### Справочник `MOVA_ШаблоныПроизводственныхЗаявок`

Используется для рецептов сырья и шаблонов палет тары.

Реквизиты:

- `Наименование`
- `ВидШаблона`: Сырье / Тара
- `Напиток`: Пиво / Лимонад
- `Активен`

Табличная часть `Состав`:

- `ГруппаЗаявки`: Зерно / ХмельИДрожжи / Компоненты / Тара
- `Номенклатура`
- `Характеристика`
- `Количество`
- `Упаковка`

Поле `ГруппаЗаявки` обязательно: по одному шаблону пива приложение должно
создавать отдельный заказ на зерно и отдельный заказ на хмель и дрожжи.
Палета бутылок 0,33 также является строкой этого справочника, а не отдельной
логикой приложения.

### Справочник `MOVA_ПартииРозлива`

Нужен как стабильная выбираемая сущность вместо текстового имени листа Google.

Реквизиты:

- `Наименование`
- `Напиток`: Пиво / Лимонад
- `Номенклатура`
- `Характеристика`
- `Серия`
- `ПлановыйОбъем`
- `ДатаРозлива`
- `Источник`
- `ИдентификаторGoogleТаблицы`
- `ИдентификаторЛиста`
- `Закрыта`

Партии могут импортироваться из последних листов Google-таблицы, но после
импорта должны храниться в 1С и использоваться в документах по ссылке.

### Документ `MOVA_ОтчетОРозливе`

Нужен для фиксации фактического результата розлива и построения отчёта по
потерям. Заказ на перемещение эту информацию не хранит.

Реквизиты:

- `Организация`
- `Подразделение`
- `ПартияРозлива`
- `ДатаРозлива`
- `ОбщийОбъем`
- `Ответственный`
- `Комментарий`
- `СтатусСинхронизации`

Табличная часть `Продукция`:

- `Назначение`: Продажа / Брак / Лаборатория
- `Номенклатура`
- `Характеристика`
- `Серия`
- `ВидТары`
- `Количество`
- `Объем`

Процент потерь рассчитывается из общего объёма партии и фактического объёма
продукции. На основании документа создаётся заказ на перемещение готовой
продукции на склад.

### Регистр сведений `MOVA_НастройкиИнтеграцииРозлива`

Хранит настройки Google-таблиц для пива и лимонада:

- `ВидНапитка`
- `ИдентификаторТаблицы`
- `ДиапазонИлиЛист`
- `Активна`

Секрет доступа не должен храниться в приложении. Он хранится на стороне 1С
или защищённого интеграционного сервиса.

### Дополнительные свойства и статусы

Новые отдельные документы для копирования, редактирования, отмены и возврата
не нужны. Это операции над `ЗаказНаПеремещение`.

Но необходимо настроить дополнительные свойства:

- `MOVA_ОперационныйСтатус`: Создано / Подтверждено / Отгружено /
  НедостаточноСырья / НедостаточноТары / Возврат / Отменено
- `MOVA_ЕстьДефицит`: булево
- `MOVA_Шаблон`: ссылка на `MOVA_ШаблоныПроизводственныхЗаявок`
- `MOVA_ПартияРозлива`: ссылка на `MOVA_ПартииРозлива`
- `MOVA_ИсходнаяЗаявка`: ссылка на `ЗаказНаПеремещение`

Признак дефицита рассчитывается сравнением строк заявки с доступным остатком
склада. Заявка при дефиците всё равно создаётся и выделяется в приложении.

## Отображение процессов ТЗ

### Сырье

Один или несколько заказов со склада сырья на производственный склад.
Зерно и хмель/дрожжи создаются отдельными заказами согласно ТЗ.

### Тара

Заказ со склада тары на производство. Палета является шаблоном заполнения
количества, но в документ записывается фактическая номенклатура и количество.

### Готовая продукция после розлива

Заказ с производственного склада на склад готовой продукции.

Сам выпуск продукции и отчёт по потерям не заменяются заказом на перемещение:
для них требуется отдельный endpoint создания документа выпуска и отчёт.

### Возврат сырья

Заказ с производственного склада обратно на склад сырья.

### Этикетка и передатирование

Создаются два связанных заказа:

1. Со склада готовой продукции на производство.
2. С производства обратно на склад.

Связь хранится в `MOVA_СвязанныйЗаказUID`.

## API

Первый рабочий этап:

- `GET /production/requests` — список заказов на перемещение с признаком MOVA
- `POST /production/requests/create` — создание заказа на перемещение
- `GET /production/catalog` — номенклатура, характеристики и упаковки
- `GET /production/warehouses` — доступные склады
- `GET /production/stock` — остатки по складу
- `POST /production/requests/change-status` — изменение статуса заказа

Дополнительные endpoints полного ТЗ:

- `GET /production/templates` — шаблоны сырья и палет
- `POST /production/requests/copy` — копирование заявки
- `POST /production/requests/cancel` — отмена заявки
- `POST /production/requests/update` — редактирование заявки
- `GET /production/batches` — партии розлива
- `POST /production/batches/sync` — загрузка партий из Google
- `POST /production/bottling-reports/create` — запись отчёта о розливе
- `GET /production/bottling-reports` — отчёт по датам и потерям
- `GET /production/balances` — сырьё и тара на производстве

## Минимальный демонстрационный контур

Для демонстрации первого живого процесса достаточно:

1. Создать `MOVA_ШаблоныПроизводственныхЗаявок`.
2. Заполнить один шаблон Lager с двумя группами заявки.
3. Реализовать `GET /production/templates`.
4. Из выбранного шаблона создавать два стандартных `ЗаказНаПеремещение`.
5. Показывать созданные заказы и их статусы в приложении.

Партии и документ отчёта о розливе нужны для следующего законченного сценария,
но не блокируют демонстрацию перемещения сырья.

## Требуется уточнить в 1С перед включением записи

- значения `ХозяйственнаяОперация` для каждого направления;
- стартовый `Статус` нового заказа;
- `СпособДоставки` и `ВариантПриемкиТоваров` для каждого правила перемещения;
- определить элементы `Справочники.Склады`, соответствующие складам сырья,
  тары, производства и готовой продукции;
- обязательность `ОрганизацияПолучатель`;
- правила заполнения `Назначение`;
- создаётся ли документ перемещения автоматически на основании заказа.
